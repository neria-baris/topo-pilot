# tools/hwsb: written contract (job 0161; derived from HWSB-DESIGN-v1)

**Authority.** `tools/hwsb/PROTOCOL_HWSB_v1.md`, a byte-for-byte copy of `agent-handoff/planning/responses/HWSB-DESIGN-v1.md` (sha256 `db0db31a8ebcd783647babd70c8ab698c6dacf0b128373e0c8c7cb490577e705`; it becomes HWSB-FROZEN-v1 at the execution freeze). Authority for stage B: owner addendum 32. Section marks (§n), KB, B, DRB, RC and OPEN numbers refer to the protocol.

**Precedence.** The protocol wins on any conflict; a difference is a contract defect to report, never to resolve in code. `CONTRACT.json` holds the machine-readable values (exact values are strings for `fractions.Fraction`). This file fixes names, signatures, shapes, dtypes, streams, record schemas, report keys, the store layout and the meter binding, so that the two independent test authors (`TEST_PLAN.md`) can write tests before any module exists. It changes no scientific choice. Where the protocol leaves a detail open, the simplest consistent option is fixed in §14 "Choices" (cited as "choice n"); each is open to a coordinator ruling.

**Nothing here authorises a run.** No training, real-process sampling, metered run or store write follows from this contract.

## 0. Conventions

- **Run** with `X:/Downloads/projects/topo-pilot/topo-pilot/.venv/Scripts/python.exe -s` and `PYTHONPATH=<worktree>/src`.
- **Model keys.** Every per-model map is keyed by the **int** master (620201, 620202; dry 629901, 629902), iterated in `plan.masters` order. Per-(model, side) maps are keyed by `(j, s)` tuples, `s` ∈ {`"-"`, `"+"`}; in JSON records such a key is written `f"{j}:{s}"`.
- **Numbers.** Exact quantities (σ, neighbour, M, α, F_plan, Z_bound, δ) are `Fraction`s; JSON records write Fractions as `str(Fraction)`. Gate statistics are float64; equality passes wherever the protocol says "≥" or "≤". Means are `c1_means.tree_mean`; SDs use `ddof=1`; SE = SD/√n.
- **Statuses** are full strings: `PASS`, `FAIL` (a decision gate that ran and failed), `REPORTED` (report-only gates), `NOT_RUN`, `NOT_RUN/NO_CHART`, `INCONCLUSIVE/<REASON>`, `FAIL_TECHNICAL/<REASON>`. A technical stop is raised as `HwsbStop(status, reason)` (in `hwsb_config`; subclass of `RuntimeError`; attributes `status`, `reason`). Exception map: choice 20.
- **Writes** only inside the directory passed as `out` (or the explicit path argument), by exclusive create (`stage_records.write_new`, `stage_records.save_npz`), except: `GATES.jsonl` (`stage_records.record_gate`), `STAGES.jsonl` (`hws_records.append_stage_event`), the chart ledgers (`c1_chart.ConstructionLedger`), the study ledger (`hwsb_driver.ledger_append`, atomic replace) and `logs/`. ArtifactStore writes go through `ArtifactStore.save` (content-addressed, idempotent for identical content, `CHECKSUM_MISMATCH` otherwise). `cpu_ledger.json` is written only by the meter.
- **Hygiene (§6.4 rule 1).** Until P-SCHED rule 3 holds, no function is called with an `out` or store under `X:/Downloads/projects/topo-pilot/` that writes a `.npz`, `.npy` or ArtifactStore artifact. Tests use pytest `tmp_path` with `--basetemp X:/Downloads/topo-scratch/test_hwsb-<job>/pytest`; the dry run uses `X:/Downloads/topo-scratch/hwsb-dry/`, where no file is named `HIST_*.npz`.
- **No foreign payload access.** No function opens or hashes any `payload.npz`, `state.pt` or `sealed/` file of another store, any C2ND file, `k4b-store/SEALED_VALIDATION.json`, or an E4 checkpoint payload. The only foreign history reads are the two named in the execution AUTH (RC-16): KB5 (the S3 w\* table of `hws-store`, sha256-checked) and the H2-B identity count over `hws-store/hist/**/W12-q1-s1.75-p0.2.npz` (key `canon32` only). - **Plans.** Every data and training function takes a `Plan` (§1.2), so the dry run drives the same code on tiny sizes. `REAL_PLAN` is the only plan that may touch `hwsb-store`.

## 14. Choices (where the protocol leaves something open; simplest option; the protocol wins)

1. **No private names.** `hws_driver._needle_in` is used only through the unchanged `seed_search`; `DatasetStage._sample_all` and the `LearnerStage.run` `save` closure are mirrored, not imported.
2. **Plans.** One code path with a `Plan` argument serves the real run and the dry run; `REAL_PLAN` is frozen from CONTRACT.
3. **Dry streams and IDs.** `("data", "hwsb-v1", "DRY", <case>, <role>[, <master>])` with masters 629901/629902 and replicate strings `hwsb-v1/DRY/<case>/<role>[/<master>]`; the dry plan refuses real masters.
4. **Train/dev ObservationSet config** adds `study` and `key` to E4's config keys; parents are the stage-B TransitionSpec and the master's EmissionSpec, consumer `"dataset"`, seed map = the data tree's `issued`.
5. **Evaluation blocks** keep the sampled row order, which is ascending sequence ID by construction; landmarks and the VAL panel are the 512 lowest IDs.
6. **Hist digest column** is `<U64` so the file loads with `allow_pickle=False`.
7. **Registry reader inputs.** `registry_digests` reads hist blocks and ObservationSets (canonicalised by the EmissionSpec parent's perm) under the store and its `superseded/`; `history_inventory` covers `artifacts/ObservationSet/`, `hist/` and `superseded/`. Hashing these own-store files is the B9a(i) requirement and happens only at EVAL.
8. **Hold CPU** is the training process's `time.process_time()` since process start (data generation included), compared with the per-model 7,275 s; the hold is checked after each checkpoint is saved.
9. **A CONTINUE at a hold exempts the rest of that model's training** from further holds (the HWS `--continue` pattern); STOP ends the model as INCONCLUSIVE/RESOURCE_OR_AUTHORITY.
10. **Run keys** `("hwsb-v1", "W12-q1-s1.75-p0.2", master)`; dry `("hwsb-v1", "DRY", <case>, master)`.
11. **B5 bootstrap** is one `bootstrap_means` call over `X_minus_<j>` of every charted model and the D4 rows (one index stream); CI ranks 125 and 4,875 of the per-draw ratio; POSITIVE_BELOW_PLANNING requires the rank-125 mean-X− value > 0 for every charted model.
12. **§10.2 literal c_min** keeps F_plan in the numerator (as the protocol's expected-value line "0.29 in the §10.2 form" does) and uses z_{1−α} only.
13. **KB7** needs VAL, which exists only at EVAL, so it runs (report only) right after the blocks are drawn in the EVAL job.
14. **B8a at EVAL** recomputes `law_bound` for w\* and requires equality with the KB4 value; the stand-in Z_bound 10⁻⁶ feeds only the report-only B6 when B8a fails.
15. **B7 measured CPU** is read from the study ledger entries of the two TRAIN jobs (stage `"TRAIN"`, `master`), which the coordinator appends from the meter ledgers.
16. **B9a(iii) N_C** is 12,288 when B6 has no N; the comparison is exact (`Fraction(float(p_D2a))`).
17. **NO_CIRCLE criterion** is `C0_CAL` or `C0_VAL` of the first failing model in master order; the reasons are in REPORT.json.
18. **Outcome order inside row 1.** A recorded technical failure, then a B1 INCONCLUSIVE, then B8a, then B9a; LADDER before CAPTURE in row 5.
19. **B6 with one charted model** runs `ladder_pilot` with that model only and is reported, not gated; with no charted model it is NOT_RUN.
20. **Exception map** (`hwsb_driver.status_of`): `HwsbStop` and `hws_worlds.HwsStop` keep their status; `c1_records.C1GateFailure` keeps a status starting `FAIL_TECHNICAL/` or `INCONCLUSIVE/`, otherwise `FAIL_TECHNICAL/NUMERICAL`; `StageFailure` `NONFINITE_LOSS` → `FAIL_TECHNICAL/NONFINITE`, `SPLIT_OVERLAP` → `FAIL_TECHNICAL/LINEAGE`, other `StageFailure` → `FAIL_TECHNICAL/BUILD`; `oracle_profile.ProfileError`, `errors.Invalid` → `FAIL_TECHNICAL/NUMERICAL`; anything else → `FAIL_TECHNICAL/UNEXPECTED`.
21. **TRAIN needs a coordinator KB_ACCEPT** bound to the KB record's sha256 (the HWS S0_ACCEPT pattern).
22. **Dry tiny model** uses warmup 20 and checkpoints (0, 100, 200) for its 200 steps, gate step 200, site `resid_post_0` (a 1-layer model has no `resid_post_3`); dry block sizes LGATE 512, CAL 1,024, VAL 1,024 so that 512 landmarks exist.
23. **Exit code 5** marks an owner STOP at a hold (INCONCLUSIVE), distinct from a technical STOP (3) and a 3× pause (4).
